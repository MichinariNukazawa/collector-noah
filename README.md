# Collector Noah

ブラウザで見た・保存した画像についての操作（クリック、別タブで開く、いいね、保存など）を記録するツール。
Chrome / Firefox 拡張と、ローカルで動く Python 製の受信アプリの2点セットで、両方そろって初めて動く。
記録は利用者のマシンの中だけに保存され、Collector Noah が外部のサービスへデータを送信することはない。

集まるのは「いつ、どのサイトで、どの画像に、何をしたか」という事実の記録。好みの判断や分析は Collector Noah の仕事ではなく、記録を読み取る側（利用者や別のアプリ）が行う。

## できること

- 対応サイトで、画像をクリックした、別タブで開いた、いいね・保存・ブックマーク・フォローした、という操作を自動で記録する
- 右クリックから、画像1枚だけ、またはページ内の画像をまとめて、明示的に記録を送れる
- 受信アプリが止まっていた間の記録は拡張側にためておき、復旧すると自動で送り直す
- ポップアップで、今日の記録件数・最後の受信時刻・未送信の有無が確認できる（記録のたびに通知は出ない）
- 記録は JSONL ファイルと画像ファイルとして手元に残り、後からプログラムで読み取れる。受信アプリの API からも取得できる

想定する用途は、たとえばローカルの画像生成システムが「その人がどんな画像を好むか」を推し量る材料にすること。設計の考え方は [PURPOSE.md](PURPOSE.md) にある。

対応サイトと、サイトごとに記録する操作:

| サイト | 拾うもの |
|---|---|
| X | ツイート画像、いいね、ブックマーク、開いた画像 |
| Pixiv | 作品画像、いいね、ブックマーク、開いた画像 |
| Danbooru | 投稿画像、お気に入り、クリック、開いた画像 |
| DMM / FANZA | 商品画像、お気に入り、クリック、開いた画像（`dmm.co.jp`。FANZAは同じドメイン） |
| DLsite | 商品画像、お気に入り、フォロー |
| Melonbooks | 商品画像、ほしいもの、お気に入り、クリック、開いた画像 |

購入履歴は記録の対象外。

## 仕組み

```
ブラウザ拡張 ── http://127.0.0.1:8765 ──▶ 受信アプリ ──▶ ~/.local/share/collector-noah/
（対応サイトで操作を検出）   （トークン認証）      （JSONL と画像を保存）
```

- 拡張がアクセスできるのは、対応サイトのページと、同一マシンの受信アプリ（127.0.0.1:8765）だけ
- 受信アプリは Python 標準ライブラリだけで動く。既定では画像を取得元へ取りに行かず、拡張から渡された画像を保存する
- 初期状態は「停止中」。設定で明示的に有効にするまで、何も記録・送信しない

API やデータ形式の詳細は [機能仕様書](SPEC.md) と [schemas/](schemas/)。

## インストール・初期設定

### 前提

- Python 3（受信アプリ用。追加のライブラリは要らない）
- Chrome / Edge または Firefox（115 以降）
- 拡張はストアで配布していない。このリポジトリから自分でビルドして読み込む
- 受信アプリを常駐させる手順は systemd（Linux）向け。手動起動なら OS を問わない

### 1. ビルドする

```bash
git clone <このリポジトリ>
cd <clone 先>
python3 build.py
```

`dist/chrome` と `dist/firefox` ができる。zip 形式の配布物は用意していない。

### 2. 受信アプリを起動する

systemd ユーザサービスで常駐させる（推奨）:

```bash
mkdir -p ~/.config/systemd/user
cp collector/collector-noah.service ~/.config/systemd/user/
# ユニットの WorkingDirectory を clone 先のパスに書き換える（既定は %h/projects/noah）
systemctl --user daemon-reload
systemctl --user enable --now collector-noah.service
```

手動で起動する場合:

```bash
# リポジトリのルートで
python3 -m collector.server --no-download
```

起動表示に `endpoint: http://127.0.0.1:8765` と `download=none` が出れば起動している。終了は Ctrl+C。ポート使用中のエラーで終了した場合は、すでに別の受信アプリが動いている。二重に起動せず、そちらの状態を確認する。

初回起動時に、認証用トークンが `~/.local/share/collector-noah/token` に自動で作られる。

稼働確認:

```bash
systemctl --user is-active collector-noah.service   # active と出る
curl -s http://127.0.0.1:8765/api/health             # {"ok": true, "version": "0.1.3"} が返る
```

サービスの停止・再起動・解除や、ログイン前から起動する設定（linger）は [collector/README.md](collector/README.md) のサービスの手順。

### 3. 拡張を入れる

#### Chrome / Edge

1. `chrome://extensions` を開く
2. デベロッパーモードを ON にする
3. 「パッケージ化されていない拡張機能を読み込む」→ `dist/chrome` を選ぶ
4. 読み込み後、拡張カードに `Collector Noah 0.1.x`（`manifest.chrome.json` の version）が表示されることを確認する。古い版が表示されたら、古いコピーが混在していないか確認する

#### Firefox

1. `about:debugging#/runtime/this-firefox` を開く
2. 「一時的なアドオンを読み込む」→ `dist/firefox/manifest.json` を選ぶ

Firefox の一時アドオンはブラウザの再起動で消える。常用するには署名済みアドオンが必要。

### 4. 拡張と受信アプリをつなぐ

両者は「Endpoint」と「Token」でつながる。拡張を入れると設定画面が自動で開く。閉じた場合はツールバーの拡張アイコンから「設定」を開く。

1. 「Token」に、`~/.local/share/collector-noah/token` の中身を入れる。「Endpoint」は既定の `http://127.0.0.1:8765` のまま使う
2. 「接続テスト」を押す。「接続OK（Collector ver …）」と出ればつながっている。「受信アプリには繋がりましたが、Tokenが違います。」なら Token を入れ直す。「接続できません。」で始まる表示なら受信アプリの起動と Endpoint を確認する
3. 「拾うサイト」で記録したいサイトが選ばれていることを確かめる
4. 「収集を有効にする」にチェックして「保存」を押す。「保存しました。」と出る

Token が空、または Endpoint が不正なままでは収集を開始できない。Endpoint に使えるのは、ループバック（127.0.0.0/8・localhost・::1）かつポート 8765 のものだけで、パス・クエリ・フラグメントは付けられない。

### 5. 記録されているか確認する

ツールバーの拡張アイコンを開き、ポップアップに「収集中」と出ていることを確かめる。対応サイトで画像をクリックすると記録され、ポップアップの「最後の受信」の時刻が更新される（未受信なら「受信した記録はまだありません」と表示される）。記録の成功通知は出ない。

## 基本的な使い方

| やりたいこと | 操作 |
|---|---|
| 記録を一時的に止める | ツールバーの「一時停止」→「停止中」。止まっている間の新しい操作は記録しない（停止前の未送信分は残る） |
| 再開する | 「再開」を押す。その時点から収集と再送を再開する |
| あるサイトだけ止める | 設定の「拾うサイト」で外して「保存」 |
| 受信アプリが止まっていた | 復旧して接続が通ると未送信分は1分ごとに自動再送される。「未送信を再送」でも送れる |
| 未送信を捨てる | 「未送信をクリア」→ 確認画面で「削除」。元に戻せない（受信済みの記録は消さない） |
| 動かなくなった | ポップアップの「問題を報告」で共有用に情報を絞った Markdown をコピーし、AI や Issue に貼る |

未送信が200件に達すると「キュー満杯」になり、新規受付が止まって `!` が表示される。復旧・再送・消去で空きができると「収集中」に戻る。ポップアップの「未送信」が「—」なら、送信に失敗した記録は残っていない。状態ごとの表示と対処の一覧は [機能仕様書の「状態の表示」](SPEC.md#状態の表示)。

## データとプライバシー

### 保存場所と中身

記録はすべて利用者のマシン上に保存される。

```
~/.local/share/collector-noah/
  token              認証用トークン
  events.jsonl       記録したイベント
  inventory.jsonl    棚卸し（任意機能）の記録
  gaps/records.jsonl 収集の警告（診断用）
  images/            受信した画像（SHA256 のファイル名）
```

データディレクトリとトークンファイルには、所有者だけが読める権限（700 / 600）が設定される。

### 受信アプリへ送るもの

- 画像URL、ページURL、サイト、操作の種類、時刻
- 対象に付随する本文（投稿文・キャプション・説明文など、最大2,000字）
- サイトが対象に付けたタグ（最大30個）
- 作者の表示名と ID
- 本人が投稿したコメント・返信の本文（送信が成立したことがサイトの表示で確認できた場合だけ）

### 送らないもの

- ページ全体の本文（対象に付随する本文だけが例外）
- Cookie、フォームの入力値
- スクリーンショット
- 他人のコメント

### 任意の追加機能（どちらも既定 OFF）

- 閲覧サンプル: ON にすると、許可サイトの前面タブで、実寸が幅・高さとも300px以上の画像のうち、画面上の画像面積の50%以上が表示領域に1秒以上連続して入ったものだけを候補にし、UTC 日次で重複を除いた候補の10%・100件/日までを送る。未送信分は30日で消える
- 棚卸し: ON にすると、サイトのボタンやリンクの種類・属性・件数だけを送る（設計改善のため。本文や入力値は送らない）

### 通信と認証

- 拡張の送信先は、同一マシンの受信アプリ（`http://127.0.0.1:8765`）だけ。受信アプリもループバック以外では起動できない
- Collector Noah が、記録したデータを外部のサービスへ送信することはない。ただし受信アプリのダウンロードモード（任意指定、既定は無効）を有効にすると、いいね・保存などの画像を取得元のサイトへ要求する
- 認証はトークン方式で、稼働確認（`/api/health`）を除くすべての API に `X-Atelier-Token` ヘッダが必要。トークンの値は画面やログに表示されない

### データの削除

- 受信済みの記録を消すには、受信アプリを止めて `~/.local/share/collector-noah/` を削除する
- 拡張側にたまった未送信分は、ポップアップの「未送信をクリア」で消せる（受信済みの記録は消さない）

なお、データがローカルにあることは「完全に安全」という意味ではない。トークンやデータファイルの扱いは、利用者のマシンの管理状態に依存する。

## 制限事項・トラブルシューティング

### 制限

- 対応は上記6サイトのみ。サイトの DOM 変更で動かなくなることがある。壊れたらアダプタを直す
- Firefox の一時アドオンは再起動で消える
- 画像を取得できなかった場合は、イベントだけが残り、取得できなかった理由が記録される
- 送信に失敗したイベントは拡張内に最大200件（うち閲覧サンプルは50件）までため、1分ごとに再送する
- 著作権・利用規約は各自で確認すること。ローカルでの個人的な記録・分析のためのもので、再配布しない
- アダルトサイトを含むため、収集は明示的に有効にしたときだけ動く

### うまくいかないとき

- 「接続できません」: 受信アプリが起動しているか（`systemctl --user is-active collector-noah.service`、または `/api/health` の応答）、Endpoint が既定のままかを確認する
- 「受信アプリには繋がりましたが、Tokenが違います。」: `~/.local/share/collector-noah/token` の中身と、設定画面の Token が一致しているかを確認する
- 記録されない: ポップアップの状態が「収集中」か、「拾うサイト」でそのサイトが有効かを確認する。「最後の受信」が更新されない場合は、未送信がたまっていないかも見る
- 「キュー満杯」: 受信アプリを起動して「未送信を再送」するか、不要なら「未送信をクリア」で空ける
- それでも直らないときは、ポップアップの「問題を報告」から共有用の Markdown をコピーして Issue に貼る。完全版の診断はローカルファイルとして保存でき、受信アプリに保存された収集の警告件数と直近10件が入る
